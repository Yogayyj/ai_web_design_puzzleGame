本节课不是马上写代码，而是先体验谜题、拆解网页游戏结构，并确定自己的 Puzzle Game 项目方向。

网页 = 内容 + 样式 + 交互 HTML = 骨架 CSS = 外观 JavaScript = 大脑

本课目标

让学生先建立“网页项目”意识，再把 puzzle game 从玩家视角转换成设计师视角。

🌐

认识网页

理解网页由标题、文字、图片、按钮、输入框、链接、布局和交互组成。

🧩

拆解游戏

区分游戏主题、规则、玩家输入、反馈方式和胜利条件。

🤖

学会提问

使用 AI 生成主题点子，但要能筛选、修改和表达自己的需求。

Slide 1 / 9

今天的问题

我们不只是玩 Puzzle Game，而是要成为设计 Puzzle Game 网页的人。

玩家会问

我怎么玩？怎么赢？答案对不对？

设计师会问

规则是否清楚？反馈是否及时？网页是否好用？

AI 可以帮忙

生成点子、写初稿、解释代码、提出修改建议。

Slide 2 / 9

你玩过哪些 Puzzle Game？

请说出你玩过或见过的谜题游戏。

教师提示

引导学生发现：Puzzle Game 的核心不是画面复杂，而是“让玩家思考并做判断”。

Slide 3 / 9

活动：Puzzle Game 如何一步步变成网页？

请按顺序体验或观察三个例子，思考：玩家输入、规则、反馈分别在哪里？

①

传统数独

从纸面数字谜题开始：规则固定，玩家用逻辑填空。

打开 Sudoku PDF

②

Murdoku

数独规则进入网页：网页能呈现题目、限制步骤，并让玩家在线操作。

打开 Murdoku

③

Type Help Game

从“解题”走向“网页互动”：文字、输入、按钮和反馈共同组成游戏体验。

打开 Type Help Game

引导问题

请学生比较：哪一个最像纸面谜题？哪一个最像网页游戏？如果要自己制作，需要准备哪些 HTML 内容和哪些 JavaScript 互动？

Slide 4 / 9

课程最终成果

6节课后，每位学生完成一个可以上传到 GitHub Pages 的 Puzzle Game 网页。

你的 Puzzle Game 网页 ├── 游戏标题 ├── 游戏规则 ├── 谜题内容 ├── 玩家输入或点击按钮 ├── 判断答案 ├── 显示反馈 └── 发布到 GitHub Pages
Slide 5 / 9

网页 = 内容 + 样式 + 交互

骨

HTML

决定网页上有什么：标题、文字、图片、按钮、输入框。

衣

CSS

决定网页长什么样：颜色、字体、排版、边框、背景。

脑

JavaScript

决定网页会不会动：点击按钮、判断答案、显示反馈。

Slide 6 / 9

一个 Puzzle Game 网页需要什么？

游戏名称与背景

让玩家知道这是一个什么游戏，为什么要玩。

游戏规则与目标

告诉玩家要做什么，怎样算赢。

谜题内容与线索

题目、文字、数字、嫌疑人、地点、物品、图片等。

玩家操作与反馈

输入答案、点击选项、提交按钮、正确/错误提示。

Slide 7 / 9

AI 协作示范

提示词要包含：我是谁、我要做什么、难度要求、输出格式。

我是一名初二学生，正在制作一个 Puzzle Game 网页。 请帮我生成5个适合初中生制作的网页小游戏主题。 要求： 1. 不要太复杂； 2. 可以用 HTML、CSS、JavaScript 实现； 3. 每个主题包括游戏名称、玩法说明、玩家需要做什么。
Slide 8 / 9

细化一个主题

我想做一个 Murdle-style mystery puzzle 网页。 请帮我设计一个简单案件。 要求： 1. 有3个嫌疑人； 2. 有3条线索； 3. 玩家需要根据线索判断真正的答案； 4. 适合初二学生理解； 5. 最后给出正确答案和解释。

教师提醒

AI 生成内容后必须人工检查：是否太难？是否有歧义？是否能在网页中判断答案？
