课程定位

这不是一门单纯“学代码”的课，而是一门把 AI 作为生产力工具，把创意变成网页作品的项目制课程。

目标 1

拥有一个可访问作品

每位学生完成一个 GitHub Pages 托管的 Puzzle Game 网页，可用于展示学习成果。

目标 2

理解网页基本结构

掌握 HTML、CSS、JavaScript 在网页中的作用：内容、样式、交互。

目标 3

学会与 AI 协作

不是复制答案，而是提出需求、测试效果、反馈修改，形成“人类设计 + AI生成 + 人类判断”的工作流。

可选 Puzzle Game 类型

建议初二学生从“规则清晰、页面简单、反馈明确”的类型开始。

文字谜题 Word Puzzle

例如：猜词、成语线索、单词分类、找共同点。

  • 适合语言表达强的学生
  • AI 可帮助生成题库和提示
  • 交互难度较低

数字谜题 Number Puzzle

例如：简化数独、找规律、密码锁、算式谜题。

  • 适合逻辑推理训练
  • 可做成输入答案后判断
  • 规则容易可视化

推理谜题 Mystery Puzzle

类似 Murdle 风格的线索推理：人物、地点、物品、时间。

  • 适合故事创作
  • 可结合表格、线索卡片
  • 强调信息整理与排除法

6课时课程设计

每节课建议 40–45 分钟；若课堂时间较短，可把“发布与展示”延伸为课后完成。

01

从玩家到设计师：什么是 Puzzle Game 网页？

学生体验 2–3 个简单谜题，拆解“主题、规则、输入、反馈、胜利条件”。完成自己的游戏构想表。

产出：游戏概念卡AI任务：生成3个游戏点子教师重点：规则必须简单可测
02

网页三件套：HTML / CSS / JavaScript

用一个最小可运行页面理解结构：标题、说明、题目区域、输入框、按钮、结果反馈。学生修改文字、颜色和布局。

产出：第一个静态页面知识点：标签、class、button教师重点：先能看懂，再能修改
03

让谜题动起来：输入、判断与反馈

学生实现“输入答案 → 点击检查 → 显示正确/错误/提示”的基础交互。不同类型游戏可以共用同一个判断框架。

产出：可交互原型知识点：变量、事件、if判断AI任务：解释代码每一段作用
04

游戏体验设计：关卡、提示、视觉风格

加入 3 个关卡、提示按钮、计分或进度显示。学生使用 AI 生成题目，但必须人工检查难度和准确性。

产出：3关游戏版本知识点：数组、函数、页面状态教师重点：好游戏=规则清楚+反馈及时
05

GitHub 工作流：上传、修改、版本管理

建立仓库，上传 index.html，理解 repository、commit、branch、GitHub Pages。学生完成第一次线上发布。

产出：可访问网址知识点：commit、Pages、路径教师重点：保存版本，不怕试错
06

作品完善与展示：Playtest Day

同伴试玩并填写反馈：规则是否清楚、是否有趣、是否有 bug。学生根据反馈完成最终修改并进行 1 分钟展示。

产出：最终作品页活动：试玩反馈表评价：创意+功能+表达

最终作品要求

1清楚标题与游戏介绍
2至少 3 个谜题或关卡
3有输入/选择与结果反馈
4有视觉风格和说明文字
5发布到 GitHub Pages

学生可用 AI 提示词

建议把 AI 当作“助教”和“程序员搭档”，每次只让它完成一个明确任务。

我是一名初二学生，正在制作一个 Puzzle Game 网页。 游戏类型：文字谜题 / 数字谜题 / 推理谜题 目标玩家：初中生 我希望网页包括：标题、规则说明、3个关卡、输入答案、检查按钮、正确/错误反馈、提示按钮。 请你帮我生成一个适合初学者阅读的 HTML 文件，代码中加入中文注释。 要求：不要太复杂，所有代码放在一个 index.html 里，可以直接上传到 GitHub Pages。

评价标准 Rubric

维度优秀合格需要改进
游戏规则规则清楚，有挑战但不混乱基本能理解玩法玩家不知道该做什么
网页功能至少3关，反馈准确，无明显bug能完成基本判断按钮或答案判断无法正常运行
视觉设计风格统一，排版清晰页面基本整洁信息拥挤或难以阅读
AI协作能描述需求、测试、反馈并修改能使用AI生成基础代码只复制代码，不理解也不测试
展示表达能说明设计思路和改进过程能介绍作品基本功能无法解释自己的作品

核心理念：AI 不是替你完成作品的人，而是帮助你把想法变成作品的工具。
